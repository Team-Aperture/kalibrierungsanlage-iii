# Architecture

This document describes how *Die Kalibrierungsanlage III – Kapitel 0* is put together, and how to build further chapters on it.

## 1. Rendering model

### Projection

Gameplay runs in a flat world plane measured in **world units (wu)**, plus a height `z`. One floor tile is 16 × 16 wu. Rendering uses a **2:1 dimetric projection**:

```
sx = x − y
sy = (x + y) / 2 − z
```

A tile becomes a 32 × 16 px diamond, and heights map 1:1 to screen pixels. The view direction (towards the camera) is `(1, 1, 1)`, so a larger `x + y + z` is closer to the viewer.

Phaser's world coordinates *are* projected screen coordinates. Movement, collision, path finding and trigger zones never touch screen space (`src/core/projection.ts`).

### Depth sorting

Every sortable thing (props, the player, light cones) has a world-space box. `src/core/depthSort.ts` builds a "drawn-before" graph and sorts it topologically every frame. Edges are only added for pairs whose screen rectangles overlap. The separating-axis rule is:

> A is behind B when `A.x1 ≤ B.x0`, or `A.y1 ≤ B.y0`, or `A.z1 ≤ B.z0`.

This works for long and large objects (railings, the transformer, the walkway) where sorting by sprite centre fails. When the player is hidden behind a prop flagged `tall`, an x-ray silhouette is drawn so the player never loses track of the character. Collision stays on the ground plane in both cases.

### Art pipeline (no image files)

Everything visible is generated by code at boot (`src/art/`):

1. **Geometry → G-buffer** (`surface.ts`). Objects are modelled from quads, boxes, vertical cylinders and pipes in world units. Each primitive is rasterised by inverse projection; a *shader* function receives face-local coordinates and returns material + albedo. The G-buffer stores material, albedo, normal, world position and an occluder id per pixel.
2. **Baked lighting** (`light.ts`). Each room defines lighting states, for example `dark`, `darkOff` (lamp flicker) and `lit` for the Wartungszelle. Point and spot lights with Lambert shading, slab-test shadows and depth fog are summed per pixel.
3. **Palette quantisation** (`dither.ts`, `palette.ts`). The lit value is quantised onto the material's ramp of the locked **28-colour palette** with an **8×8 Bayer matrix**. Where coloured light dominates (green CRT glow, red warning lights, amber), pixels are dithered over onto that light's ramp, which gives the speckled glow of the reference prototype.
4. **Overlays** (`overlay.ts`). Animated screens, rotor glow, indicator lamps and beacons are drawn *exactly over the G-buffer pixels* of the surface they belong to, so they inherit perspective and occlusion. Light cones are additive dithered overlays.

5. **Brand art** (`brand/`). The Team_Aperture emblem and the KA-III banner are palette-indexed pixel art from the same 28 colours. They are used in three ways:
   - as DOM canvases (`ui/brand.ts`);
   - as wall paint inside room shaders (`brand/decal.ts`);
   - on monitor rasters (`brand/screens.ts`).

   See [BRANDING.md](BRANDING.md).

Each prop is baked once per lighting state. A lighting change, such as the flickering lamp or the power-up strobe, is a cheap texture swap. The player sprite (`player.ts`) is generated from hand-tuned shapes per facing (S, SE, E, NE, N, mirrored for W). It has 4 idle and 6 walk frames, at six brightness levels chosen from the light field at the player's feet.

### Resolution and crispness

The composition targets **384 × 216**. `src/game/display.ts` chooses an internal resolution so that **every game pixel covers an integer number of device pixels**, so nothing is ever blurred:

| Context | Internal resolution |
| --- | --- |
| Landscape | width 352–512, height 198–288 (≈ 384 × 216 on common screens) |
| Portrait | ≈ 270 × 311 game view on top, controls docked below |

A 16:9 strip would be tiny on a phone held upright, so portrait deliberately shows a narrower, taller window onto the same world. The camera follows the player inside room bounds, and rooms smaller than the view are centred.

CRT scanlines (aligned to game pixels), vignette and flicker are a CSS layer composited by the browser. There are no full-screen shader passes, so the same look works in WebGL and in the Canvas fallback.

## 2. Program structure

```
src/
  core/        projection, depth sort, collision, nav grid (A*), rng, events — pure, unit-tested
  art/         palette, dithering, G-buffer rasteriser, lighting, overlays, font, player, icons
    rooms/     per-room geometry + materials + lighting (no gameplay knowledge)
    brand/     Team_Aperture emblem, KA-III banner, pulse clock, CRT boot reveal, decals
  content/     layouts (shared by art + gameplay), item texts, hint texts
  game/
    app.ts     GameApp: owns state, settings, audio, input, UI; drives Phaser
    scenes/    BootScene (bakes textures), WorldScene (runs one room)
    rooms/     gameplay room definitions: props, verbs, German texts, scripts
    entities/  Player
    systems/   Veil (darkness with light holes for intro / events)
    puzzles/   pure puzzle logic (Energiepfad)
    script.ts  ScriptCtx: the API content is written against
    input.ts   keyboard + joystick
  state/       SaveData types, validation/normalisation, GameState, settings
  ui/          HTML/CSS interface: boot screen, title screen, HUD, dialogue, menus, inventory,
               terminal reader, puzzle panel, logo components
  audio/       WebAudio synthesiser (ambience + effects)
```

### Room definition (`src/game/rooms/types.ts`)

A room is data plus a few hooks:

- `bounds` and `solids(state)`: collision depends on world state, e.g. a closed gate.
- `props`: each prop has a sort box, a texture function `(state) → baseKey`, and optionally an `interact` definition with a name, approach points, a hotspot, verbs, `onItem` and `accepts`.
- `lighting` and `lightingKey(state, time, settings)`: which baked lighting state is shown.
- `zones`: trigger rectangles, such as exits and events.
- `bake(scene)`: the art module that registers the room's textures.
- `setup(ctx)`: overlays and animation hooks. `onEnter(ctx)`: scripts such as the intro.

Verbs and scripts are `async` functions using `ScriptCtx`. They can show German text (`say`), wait, play sounds, pan the camera, walk the player, give or take items, set flags and run cutscenes (`cutscene` locks input). `WorldScene.interact` walks the player to the nearest reachable approach point first and ignores duplicate activations while a verb runs.

### World state and saving

All persistent changes go through `GameState`: flags, inventory, door states (`LOCKED → POWERED → UNLOCKED → OPEN`), the puzzle rotation, hints used and inspected objects. Saves are written on every meaningful change, every few seconds for the position, and on pause, on `visibilitychange` and on `pagehide`.

`state/save.ts` validates untrusted JSON. `normalize()` repairs impossible combinations: a solved panel always means an open door, and you are never left beyond a closed door. Cutscenes commit their final state before animating, so a reload mid-animation always shows a consistent world.

### Puzzle framework

Puzzles are pure modules (`src/game/puzzles/*`) with an `evaluate` function and reversible moves, rendered by an accessible HTML panel. The panel is a crisp pixel-art canvas with real `<button>`s over the tiles. Hints live in `src/content/hints.ts` as three stages per puzzle id. The unit tests enumerate the full state space of the Energiepfad puzzle (4⁷ configurations).

## 3. Adding a chapter or room

1. Write a layout file in `src/content/rooms/` (boxes in world units).
2. Write the art in `src/art/rooms/<room>.ts`: a background surface, prop builders and a `LIGHTING` table. Add a bake module that registers texture keys.
3. Write the gameplay room in `src/game/rooms/<room>.ts`: props with verbs and German text, `solids`, `zones`, `onEnter` and `setup`.
4. Register the room in `src/game/rooms/index.ts` and its id in `RoomId` (`src/state/types.ts`). Add new items to `ItemId`, `content/items.ts` and `art/icons.ts`.
5. Extend `tests/unit/rooms.test.ts`: every interaction point must be reachable, and gates must block until opened.

The developer art lab (`npm run dev`, then open `/?lab` or `/?lab&room=schleuse`) renders a room's bake without the engine, for fast visual iteration.
